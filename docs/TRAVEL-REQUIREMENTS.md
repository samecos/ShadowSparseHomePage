# 旅行板块需求调研

> 调研日期：2026-09-12  
> 状态：需求已确认；旅行规划 MVP 已实现  
> 适用范围：个人主页 `/travel` 旅行记录板块

## 1. 结论先行

旅行板块不应只是现有“照片”和“地图”的再包装，而应增加一个名为「旅行」的容器，把一次旅行从计划、出发到回忆串成同一个对象。第一目标是成为一个轻量的提前规划工具，旅行后的回顾是可选的延伸。

建议采用“规划优先、记录低摩擦、回顾可选、隐私默认收紧”的方向：

- 旅行前解决“我准备去哪里、怎么走、预订材料在哪里、还有什么没准备好”。
- 旅行中解决“今天在哪里、发生了什么、怎样低成本留下记录”；手机端可在授权后读取当前位置。
- 旅行后按需生成回顾页，必要时再生成适合打印的 PDF。
- 计划中和进行中的旅行都只对站长和授权 Agent 可见；进行中的旅行不出现在公开主页。
- 不做多人协作，但 HERMES Agent 可以在授权范围内创建、整理和更新旅行内容。

## 2. 现有站点可复用能力

当前站点已经具备旅行板块所需的大部分“记忆素材”：

| 现有能力 | 可以复用的内容 | 当前缺口 |
| --- | --- | --- |
| `/photos` 照片库 | 上传、EXIF 时间、地点、经纬度、收藏、公开/私密、批量整理 | 没有旅行归属与旅程分组 |
| `/map` 地图故事 | 地图点位、照片、标题、文字、标签、点位拖拽 | 没有日期范围、旅行阶段和每日行程 |
| `/says` 日常说说 | 短文字、心情、地点、图片、时间 | 不能挂到某一次旅行或某一天 |
| `collection` / HERMES | 收集攻略、链接、灵感和待整理内容 | 没有“属于某次旅行”的关联 |
| JSON 文件存储与管理员鉴权 | 适合个人站点的小规模内容管理 | 需要新增旅行集合和迁移策略 |
| `/api/upload` | 当前已支持图片和 PDF 上传，单文件上限 8MB | 预订材料不能直接放在公开的 `public/uploads`，需要私有文件存储与授权下载 |

因此，推荐新增 `Trip` 作为聚合层，尽量引用现有照片、地图故事和说说，而不是复制三套数据。

## 3. 外部产品模式观察

调研了三类成熟产品，得到的共同模式是“计划集中化、途中低摩擦记录、结束后自动成故事”：

| 产品 | 已验证的需求模式 | 对本站的启发 |
| --- | --- | --- |
| Wanderlog | 行程、地图、预订、路线、清单、预算、协作和离线访问集中在一处 | 旅行前需要一个清晰的行程骨架，但本站只保留个人真正会维护的字段 |
| TripIt | 将交通、住宿、日程、文件和分享集中到一份总行程，并支持日历同步与提醒 | 预订信息适合成为行程附件/链接，不必在本站重复做预订 |
| Polarsteps | 规划、路线、地点、照片、故事、统计、隐私、实时分享，以及结束后的旅行书 | 旅行中应以时间线和地图为主；旅行后可自动生成可编辑的回顾页 |

可参考的官方页面：

- [Wanderlog Travel Planner](https://wanderlog.com/)
- [TripIt 免费版与 Pro 功能](https://help.tripit.com/en/support/solutions/articles/103000063396-tripit-or-tripit-pro-)
- [Polarsteps Travel Tracker](https://www.polarsteps.com/travel-tracker)
- [Polarsteps Travel Book](https://support.polarsteps.com/hc/en-us/articles/24005113311634-What-is-a-Travel-Book)

## 4. 目标用户与核心任务

### 主要用户：站长本人

希望提前把一次旅行安排清楚：日期、地点、交通、住宿、准备事项和相关材料都能在一个地方继续修改。旅行中可以顺手记录，旅行后再决定是否整理成公开内容。

### 操作代理：HERMES Agent

Agent 不是协作者账号，而是站长授权的操作入口。它可以通过现有 HERMES Token 读取和更新私密旅行、整理攻略、创建行程项目、维护清单，并在授权范围内上传预订文件；公开发布或改变隐私状态建议始终需要站长明确指令。

### 次要用户：访问主页的人

他们主要阅读已经完成的旅行故事，关注目的地、照片、路线和个人感受，不需要看到站长的预订号、待办事项或实时位置。

### 核心 Job-to-be-done

> 当我准备一次旅行时，我希望用一个轻量的页面收拢完整计划、预订材料和待办事项；在路上能用几秒钟记录一个地点或瞬间；回来后如果值得保存，再把这些碎片整理成一篇旅行记忆。

## 5. 三阶段需求

优先级说明：P0 为首期必须有，P1 为首期后最值得补齐，P2 为有明确需求再做。

### 5.1 旅行前：出发前的准备与期待

目标：让旅行从“一个想法”变成一份可执行、可继续修改的计划。

| 编号 | 优先级 | 需求 | 关键字段/行为 |
| --- | --- | --- | --- |
| PRE-01 | P0 | 创建旅行 | 标题、目的地、开始/结束日期、封面、标签、状态 `planning`、可见性 |
| PRE-02 | P0 | 计划概览 | 显示目的地顺序、总天数、出发倒计时或日期提示 |
| PRE-03 | P0 | 每日行程 | 按天添加地点/活动；可填写时间、标题、备注、地址/坐标、外部链接；支持调整顺序 |
| PRE-04 | P0 | 准备清单 | 行李、证件、设备、购买、出发前事项；可勾选完成并保留未完成状态 |
| PRE-05 | P0 | 地图预览 | 将计划地点放到地图上，支持从地图点进入该日行程 |
| PRE-06 | P0 | 预订信息与文件 | 交通、住宿、活动三类；保存名称、时间、地址、链接、确认号和图片/PDF 附件；整个模块默认私密 |
| PRE-07 | P1 | 预算草稿 | 预算总额、币种、计划支出分类；暂不要求实时汇率或多人分账 |
| PRE-08 | P0 | Agent 操作 | HERMES 可以创建/编辑旅行、行程、清单和预订记录，也可以代为上传文件；所有操作必须经过现有 Agent Token 鉴权 |
| PRE-09 | P1 | 攻略/灵感关联 | 将 HERMES 收藏的链接、照片或笔记挂到某次旅行，作为“想去/参考”清单 |
| PRE-10 | P2 | 外部导入 | 从邮件、截图、地图或旅行平台自动解析行程；需要额外权限和第三方服务 |

旅行前的最小闭环是：

`创建旅行 → 加入日期与目的地 → 安排行程 → 上传预订材料 → 勾选准备事项 → 保存为私密计划`

### 5.2 旅行中：低摩擦的现场记录

目标：不打断旅行本身，用最少操作留下“时间、地点、内容”三种上下文。

| 编号 | 优先级 | 需求 | 关键字段/行为 |
| --- | --- | --- | --- |
| DUR-01 | P0 | 开始旅行 | 将状态从 `planning` 切换为 `active`，显示当前天数和今日行程 |
| DUR-02 | P0 | 快速记录 | 一张/多张照片、短文字、心情、地点、时间；支持直接归入当天或某个行程点 |
| DUR-03 | P0 | 时间线 | 按日期和地点展示计划、照片、地图故事、说说；允许补记和修改 |
| DUR-04 | P0 | 地图联动与当前位置 | 手机端在用户授权后读取当前位置；记录点位与照片/文字互相跳转；拒绝授权时回退到 EXIF 坐标或手动选点 |
| DUR-05 | P0 | 进行中强制私密 | `active` 状态不可被访客访问，也不出现在首页、公开地图或公开 API；仅站长和授权 Agent 可见 |
| DUR-06 | P1 | 离线草稿 | 无网络时允许保存文字和照片元数据，恢复网络后重试上传；上传失败要可见 |
| DUR-07 | P2 | 旅行期间对外分享 | 当前范围不做；如未来增加，也必须是独立的临时分享权限，不能改变旅行的私密状态 |
| DUR-08 | P1 | 当日摘要 | 根据当天记录汇总照片数、地点数、花费和一句话摘要，允许手动修改 |
| DUR-09 | P2 | 持续定位轨迹 | 后台 GPS 轨迹、路线统计和电量策略；一次性读取当前位置属于 P0，持续追踪另行评估 |
| DUR-10 | P2 | 外部实时信息 | 航班延误、天气、导航、营业时间等，需要第三方 API 和通知体系 |

旅行中的快速入口建议只保留三个动作：

1. `记一笔`：文字 + 当前时间/地点。
2. `加照片`：上传并自动读取 EXIF，补充标题即可。
3. `标记地点`：地图选点并附到今天或某个行程点。

### 5.3 旅行后：按需整理、回顾与发布

目标：把原始记录变成一篇可读、可搜索、可再次打开的个人旅行档案。

| 编号 | 优先级 | 需求 | 关键字段/行为 |
| --- | --- | --- | --- |
| AFT-01 | P0 | 结束旅行 | 将状态切换为 `completed`，保留原始计划和现场记录 |
| AFT-02 | P0 | 自动生成回顾 | 按天汇总封面、地点、照片、文字、路线和基础统计，生成可编辑草稿 |
| AFT-03 | P0 | 人工整理 | 更换封面、调整照片顺序、隐藏记录、编辑标题/引言/每日小标题 |
| AFT-04 | P0 | 公开发布 | 旅行完成后才允许选择 `private` / `public`；发布前预览，默认隐藏预订文件、确认号和精确敏感信息 |
| AFT-05 | P0 | 旅行索引 | 管理端按准备中、进行中、已完成分组；公开端只展示已完成且明确公开的旅行 |
| AFT-06 | P0 | 与现有模块互链 | 回顾页可跳转到照片库、地图故事和相关说说，避免内容孤岛 |
| AFT-07 | P1 | 旅行统计 | 天数、目的地数、照片数、记录数、移动距离（若有可靠数据） |
| AFT-08 | P1 | 按需打印 PDF | 站长主动点击后生成适合打印的 PDF；不自动生成，不影响网页回顾页发布 |
| AFT-09 | P1 | 旅行复盘 | “最喜欢的地方”“下次会怎么做”“值得再去/不必再去”等自定义字段 |
| AFT-10 | P2 | 自动视频/旅行书 | 根据回顾页生成 Reel、电子书或实体书，需要媒体编排和较高制作成本 |

旅行后的可选闭环是：

`结束旅行 → 自动生成草稿 → 选封面/删减内容 → 预览 → 公开或归档`

### 5.4 跨阶段：Agent 操作

Agent 允许代替站长执行重复整理工作，但不等同于多人协作者：

| 编号 | 优先级 | 需求 | 关键字段/行为 |
| --- | --- | --- | --- |
| AGT-01 | P0 | 旅行计划 CRUD | 创建旅行、增加/修改/排序行程、维护清单、读取私密内容 |
| AGT-02 | P0 | 预订材料管理 | 创建预订记录、上传图片/PDF、绑定到交通/住宿/活动；不得把文件 URL 暴露给公开读取接口 |
| AGT-03 | P0 | 记录整理 | 将照片、说说、地图故事和收藏关联到旅行或某一天 |
| AGT-04 | P1 | 回顾草稿 | 根据现有记录生成标题、摘要、每日小结和候选封面，结果先进入草稿 |
| AGT-05 | P0 | 发布保护 | Agent 可以按明确指令发布，但不能自行把私密旅行或进行中旅行改为公开 |

## 6. 推荐的信息架构

### 导航与入口

- 主导航新增 `旅行`，编号顺延为 `06`。
- 首页目录增加旅行模块，展示“即将出发 / 正在路上 / 最近完成”的一条摘要。
- 新增 `/travel` 旅行索引。
- 新增 `/travel/[slug]` 旅行详情，详情页内有三个阶段切换：`出发前`、`在路上`、`回来后`。

### 旅行索引页

管理端上方展示当前最重要的一次旅行，下面以较松的列表呈现：

- 准备中：目的地、日期、准备进度、预订文件数量。
- 进行中：今天的目的地、最近一条记录、私密状态提示。
- 旅行记忆：封面、标题、日期范围、目的地、照片/地点数量。

公开访客只看到“旅行记忆”，不会看到准备中或进行中的旅行。

### 旅行详情页

建议保持当前站点的“细线、低饱和、留白”语言：

- 顶部：封面、标题、目的地、日期、状态、公开状态。
- 下方：阶段指示器和时间线。
- 规划态以行程、预订文件和清单为主；进行态以今日时间线和快速记录为主；完成态以地图、照片和文字叙事为主。
- 地图是叙事结构的一部分，不单独占据全部首屏。
- 管理操作只对管理员和授权 Agent 显示；访客看到的是已发布的整理结果。

## 7. 推荐数据模型

### 7.1 旅行聚合对象（当前 MVP）

```ts
type TripStatus = 'planning' | 'active' | 'completed' | 'archived';
type TripVisibility = 'private' | 'public';

interface Trip {
  id: string;
  slug: string;
  title: string;
  summary: string;
  coverAttachmentId?: string;
  destinations: string[];
  startDate: string;
  endDate: string;
  status: TripStatus;
  visibility: TripVisibility;
  tags: string[];
  days: TripDay[];
  reservations: TripReservation[];
  entries: TripEntry[];
  recap?: TripRecap;
  lastEditedBy?: 'admin' | 'hermes';
  createdAt: string;
  updatedAt: string;
}

interface TripAttachment {
  id: string;
  tripId: string;
  reservationId?: string;
  kind: 'media' | 'reservation';
  originalName: string;
  storageKey: string;
  mimeType: string;
  size: number;
  createdBy: 'admin' | 'hermes';
  createdAt: string;
}

interface TripRecap {
  intro?: string;
  dayTitles?: Record<string, string>;
  hiddenEntryIds?: string[];
  featuredAttachmentIds?: string[];
  pdfEnabled?: boolean;
}

interface TripDay {
  id: string;
  date: string;
  title?: string;
  items: TripPlanItem[];
  checklist: ChecklistItem[];
}

interface TripPlanItem {
  id: string;
  time?: string;
  title: string;
  note?: string;
  locationName?: string;
  lat?: number;
  lng?: number;
  url?: string;
  type: 'place' | 'transport' | 'stay' | 'activity' | 'note';
}

interface TripEntry {
  id: string;
  dayId?: string;
  createdAt: string;
  type: 'note' | 'photo' | 'place';
  text?: string;
  attachmentIds?: string[];
  locationName?: string;
  lat?: number;
  lng?: number;
  visibility: TripVisibility;
}

interface TripReservation {
  id: string;
  type: 'transport' | 'stay' | 'activity';
  title: string;
  provider?: string;
  startAt?: string;
  endAt?: string;
  locationName?: string;
  confirmationCode?: string;
  url?: string;
  attachmentIds: string[];
}

interface ChecklistItem {
  id: string;
  label: string;
  category?: 'luggage' | 'document' | 'device' | 'purchase' | 'other';
  completed: boolean;
}
```

### 7.3 与现有数据的关系

- 当前 MVP 通过 `Trip.days[].items` 保存计划地点，通过 `Trip.entries[].attachmentIds` 保存沿途照片引用；现有照片、地图故事和说说仍保持独立。
- 后续可以为 `Photo`、`MapStory`、`Post` 增加可选的 `tripId` / `tripDayId`，再实现跨模块互链，避免首期迁移旧数据。
- `Collectible` 先通过标签关联，作为旅行前的灵感来源；不必把收藏模型改成旅行专用。
- `active` 旅行的公开状态必须由 API 层强制覆盖为 `private`，不能只依赖前端隐藏。
- 当前 `/api/upload` 将文件写入公开可访问的 `public/uploads`；预订附件需要独立的私有目录/存储和鉴权下载接口，公开旅行 payload 不得包含附件地址。

## 8. MVP 范围建议

### 首期做

- 旅行索引和旅行详情页。
- 创建/编辑旅行，支持标题、目的地、日期、封面、标签、状态、可见性。
- 旅行前：按天行程、地点、备注、准备清单、预订记录、图片/PDF 文件和地图预览。
- 旅行中：开始旅行、强制私密、手机端授权定位、快速文字/照片记录、时间线和地图联动；EXIF 自动提取暂留后续版本。
- 旅行后：结束旅行、按需生成回顾草稿、封面与内容整理、公开/私密发布。
- HERMES Agent 的旅行 CRUD、素材关联和预订文件上传能力。
- 管理端继续沿用现有管理员会话和 JSON 存储。

### 首期明确不做

- 航班、天气、导航等实时数据服务。
- 后台持续 GPS 轨迹、实时位置广播和旅行期间对外分享。
- 多人协作、分账、评论、点赞和社交关系；Agent 是自动化操作入口，不是协作者账号。
- 护照、银行卡等高敏感信息的托管；预订确认号和文件只允许私密存储。

## 9. 关键验收标准

1. 站长能创建一条私密旅行，填写日期与目的地，并在管理端索引看到“准备中”。
2. 站长能为某一天添加地点、准备事项和交通/住宿/活动预订记录。
3. 站长能上传图片或 PDF 预订文件；未授权请求无法读取文件，公开旅行接口不会泄露附件地址。
4. HERMES Agent 能通过授权接口创建/修改旅行计划、清单、预订记录并上传附件。
5. 站长能将旅行切换为进行中；此时旅行即使存在公开字段，也必须对访客保持私密。
6. 手机端在用户授权后能记录当前位置；拒绝授权时仍能使用文字记录或手动选点。
7. 旅行记录能按天查看，照片、地点和文字能在旅行内部关联。
8. 结束旅行后能按需生成回顾草稿，且可以更换封面、隐藏内容、编辑引言并预览。
9. 站长可以主动选择生成适合打印的 PDF，且 PDF 不会自动公开。
10. 公开旅行能通过 `/travel/[slug]` 被访客阅读，并与照片、地图故事、说说形成入口闭环。
11. 桌面端适合规划和整理，移动端适合快速记录；遵守现有低饱和、少卡片、尊重减少动效的设计规范。

## 10. 已确认决策与仍需细化的事项

以下方向已经确认：

- 第一目标是提前规划工具。

- 旅行后按需求选择生成打印 PDF。
